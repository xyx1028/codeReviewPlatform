# 版本展示同步

## 触发条件
当且仅当本次任务已在工作区根目录 `需求开发评审一致性平台/Vx.y-功能短名/` 创建或更新 `*-最终执行方案.md`，并准备声明该版本需求完成时，必须执行本 Skill。

## 必须执行的流程
1. **确定事实版本**：从本次最终执行方案的一级标题解析 `V<主版本>.<次版本>`。用户显式指定版本时以用户版本为准；禁止根据 git tag、`package.json` 或记忆猜版本。
2. **同步唯一常量**：更新 `src/lib/product-version.ts` 的 `PRODUCT_VERSION` 为该版本，例如 `V1.28`。
3. **禁止旁路硬编码**：管理员账号菜单的“查看当前版本”必须只读取 `PRODUCT_VERSION`。不得在 `src/App.tsx`、页面文案或 CSS 中再次写 `V1.x`。
4. **运行一致性检查**：执行：
   ```bash
   npm run version:check -- "需求开发评审一致性平台/Vx.y-功能短名/需求开发评审一致性平台-Vx.y功能短名-最终执行方案.md"
   ```
   脚本必须打印文档版本与产品版本；不一致时先修正，再继续。
5. **完成验证**：运行受影响前端检查（至少 `npm run web:typecheck` 和 `npm run build`），并在最终执行方案的“验证结果”中记录真实结果。

## 失败处理
- 文档标题无法解析版本：停止，不得猜测常量；先修正文档标题。
- 校验脚本提示不一致：以本次最终执行方案的版本为准更新常量，再重新运行。
- 未创建版本化最终执行方案：本 Skill 不触发；不要为了普通 Bug 或纯样式修改虚构版本目录。

## 边界
- 此 Skill 不修改历史需求文档、数据库、云端配置、git tag 或发布系统。
- “当前版本”是产品展示版本，不等同于 npm 包版本或技能包自身的版本号。
- 版本常量为单一真相；管理员账号菜单之外的任何新增版本展示也应直接 import 该常量。
