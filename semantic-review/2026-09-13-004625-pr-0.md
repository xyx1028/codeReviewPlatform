# V4 manifest identity and canonical policy hash follow-up

The change moves policy and Harness identity freezing into database triggers, splits frozen database identity from breaker-narrowed execution policy, and pins the manifest for the Worker process. Migration 0031 cannot currently be applied because its own golden check proves the SQL and Worker serializers disagree. Two additional fail-open gaps remain around mutable job identity and incomplete profile drift validation.

Watch for: **[blocking, confirmed]** migration 0031 aborts with `V4_POLICY_HASH_PARITY_FAILED`; **[medium, confirmed]** nullable/mutable manifest identity can bypass Worker mismatch checks; **[medium, confirmed]** the drift script does not prove manifest plugin enable/disable state matches the profile.

**Verdict**: NEEDS_CHANGES

## High-level view

PostgreSQL `COLLATE "C"` and Worker `localeCompare` order the current policy keys differently, so 0031 computes `ff8f5ef4…` instead of the checked-in Worker value `17037b5a…` and rolls back before installing either freeze trigger.

The enqueue trigger populates `harness_version` and `capability_contract_hash`, but those columns remain nullable and outside the immutable-policy trigger. Because the Worker rejects only truthy mismatches, clearing an identity field after enqueue skips its validation.

The manifest checker covers direct DSH versions, profile bundles, platform dependency names, Docker links, and generated migration metadata. Its Cordis validation is one-directional, allowing a manifest-disabled plugin to become enabled or a manifest-enabled plugin to become disabled without failing the check.

## SQL canonicalization fails on the checked-in default policy

**[blocking, confirmed]** `v4_canonical_jsonb_text` orders object keys with PostgreSQL `COLLATE "C"`, but `stableStringify` in both the Worker and manifest script uses `localeCompare`. In the current `web` object, PostgreSQL emits `allowHttp` before `allowedDomains`, while Node emits `allowedDomains` before `allowHttp`. Applying 0029–0031 to an isolated copy of the current 0028 schema reproduced:

```text
ERROR: V4_POLICY_HASH_PARITY_FAILED:
ff8f5ef459f00e2e1c52543a90528e379988ecd32d0f549de9bf283cd7ffc464
```

The Worker produces `17037b5a6ee572c359200e0e24997b21a3e544f30f06a13901933f273468d9eb`. The exception rolls back 0031, including `freeze_v4_job_manifest_and_policy_hash` and `copy_v4_job_policy_hash_to_run`, so enqueue/run identity freezing is not deployed.

Aligning only object-key sorting leaves another parity path. `normalize_v4_model_web_domains` uses the database default collation, Worker `normalizeDomains` uses JavaScript `.sort()`, and Unicode domains are permitted. Local PostgreSQL and Node produced different orders for `['z.com','é.com','😀.com','.com']`. Define one byte-level order across SQL, Worker, and script; normalize domains to ASCII/punycode or implement identical Unicode ordering; and add cross-runtime vectors for the default policy, mixed-case keys, non-ASCII strings, and domain arrays.

## Frozen manifest identity can be cleared after enqueue

**[medium, confirmed]** 0031 sets `analysis_job.harness_version`, `capability_contract_hash`, and `policy_hash` on insert, while `enforce_analysis_job_policy_immutable` protects only `policy_version` and `capability_policy_snapshot`. The identity columns remain nullable and mutable, so a service-role update can clear or replace them after enqueue.

`buildDeepSeekHarnessReview` checks manifest and policy identity only when each value is truthy. A cleared value reaches the Worker as `null` and skips the mismatch check. Require non-empty identity for V4 claims/startup and prevent changes once populated, with an explicit migration-only backfill path.

## Cordis plugin-state drift is checked in only one direction

**[medium, confirmed]** `scripts/v4-harness-manifest.mjs` ensures platform plugin IDs appear in the patch and explicitly disabled patch rows appear in `manifest.disabledPlugins`. It does not ensure every manifest-disabled row remains disabled or that manifest-enabled rows remain enabled. Removing `disabled: true` from `session-telemetry-otel`, `llm-deepseek`, or direct Web adapters still passes, as does disabling an ID declared in `enabledPlugins`.

Tool inventory checks cannot detect non-tool plugins such as telemetry or alternate model adapters. Validate both set directions from the resolved profile, or at minimum require every `disabledPlugins` row to be explicitly disabled and reject disabled `enabledPlugins` rows.
