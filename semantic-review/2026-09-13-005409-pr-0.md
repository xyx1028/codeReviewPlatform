## Canonical hash parity is bounded to the normalized policy contract

All sortable policy keys are fixed ASCII keys, and both SQL and Worker filter domains to `[a-z0-9.-]+`; other arrays preserve order. This removes the earlier UTF-16-versus-UTF-8 ambiguity without relying on locale behavior.

Applying migrations 0029–0031 locally completed without `V4_POLICY_HASH_PARITY_FAILED`. Independent Node and PostgreSQL calculations returned the same full `ff8f5e…464` hash, and the SQL suite finished with `ALL_V4_HARNESS_CAPABILITY_TESTS_PASSED`.

## Frozen claim identity now fails closed

`toStoryTask` normalizes absent database values to null, so factory’s explicit checks cover the real claim path. The enqueue trigger writes `policy_hash`, `harness_version`, and `capability_contract_hash`; `enforce_analysis_job_policy_immutable` rejects changing or nulling them for V4 jobs. The run trigger copies the job policy hash before insert, while profile recording and commit continue to compare the run against the job anchor.
