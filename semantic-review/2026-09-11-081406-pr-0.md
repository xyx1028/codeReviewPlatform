# 删除未引用模型配置

这次变更为模型管理增加物理删除，并通过数据库 RPC 阻止删除仍被批次或分析任务引用的模型。数据库事务记录删除审计，Edge Function 在 RPC 成功后再清理 Vault 密钥。当前实现会在正常删除前置流程中丢失 AI 导入历史，并且 Vault 清理失败后没有可重试的持久记录。

Watch for: **[高][confirmed] AI 导入历史会随前置批次删除而级联消失；[高][confirmed] Vault 清理失败后 API 仍成功且丢失定向重试所需的 secret ID；[中][confirmed] 新删除契约没有自动化测试，现有数据库测试入口也无法形成有效结果。**

**Verdict**: NEEDS_CHANGES

## High-level view

`admin_delete_model_config` 只允许没有 `review_batch` 或 `analysis_job` 引用的配置被删除，但 UI 对被引用模型给出的处理方式是先删除批次。有效 AI 导入记录的模型关联由批次派生，且存在导入记录时不能清空批次模型；先删批次会级联删除导入记录，因此新增的模型外键 `ON DELETE SET NULL` 无法保留正常工作流中的 AI 历史。

Vault 删除是无持久状态的尽力操作。清理失败时模型行及其 secret 引用已经消失，日志不记录 secret ID，当前工作区也没有补偿任务，后续无法定向重试。

迁移没有对应的 0022 数据库测试，Edge Function 也没有删除分支测试。现有 `supabase test db` 因测试 SQL 没有 TAP plan 而以零测试失败，关键删除契约没有持续回归信号。

## “先删批次”路径先于模型删除清除了 AI 导入历史

**[高][confirmed]** UI 对引用中的模型提示“请先删除已经选择了该模型的代码评审批次”（`src/App.tsx`），数据库也要求不存在 `review_batch.ai_model_config_id` 或 `analysis_job.model_config_id` 引用才可删除（`supabase/migrations/0022_delete_unreferenced_model_config.sql`）。

`populate_ai_import_model_config_id` 从批次模型派生 `ai_import_record.ai_model_config_id`，而 `validate_review_batch_model` 在已有 AI 导入或分析任务后禁止清空批次模型。因此，有效且关联该模型的 AI 导入记录必然对应一个仍引用模型的批次。按 UI 指引删除批次时，`ai_import_record.batch_id` 的既有 `ON DELETE CASCADE` 会先删除导入记录及其结果，0022 新增的 `ai_model_config_id ON DELETE SET NULL` 没有机会保留这些记录。

需要改变解除引用/归档策略，使历史记录不依赖将被删除的批次，或禁止物理删除拥有历史结果的模型。

## Vault 清理失败后没有可恢复的所有权记录

**[高][confirmed]** `handleDelete` 在数据库 RPC 成功后调用 `deleteVaultSecret`，但无论返回 `true` 还是 `false`，都会记录 `deleted` 并向前端返回成功（`supabase/functions/admin-model-config/index.ts`）。失败日志只有 `secret_present: true`，数据库模型行已经提交删除，其原 `api_key_secret_id` 也不再可查询。

代码注释称失败由后台巡检补偿，但当前工作区没有 Vault 清理队列、tombstone 或巡检实现。重试删除只会得到模型不存在，无法定位原 secret，凭据会永久残留。应在删除事务内持久化待清理 secret ID，由幂等任务重试并在成功后清除待办。

## 删除安全契约没有可执行的回归覆盖

**[中][confirmed]** 仓库没有测试引用 `admin_delete_model_config`、`MODEL_CONFIG_REFERENCED`、`MODEL_CONFIG_DELETED` 或 `is_referenced`，也没有 0022 测试文件。数据库事务、Edge Function 状态码映射、Vault 提交后清理和敏感错误处理均未被自动化覆盖。

本地回滚探针确认未引用模型可删除，批次和分析任务引用均得到 `MODEL_CONFIG_REFERENCED`，删除日志保留；静态锁分析确认并发新增引用不能越过删除。但 `supabase test db` 因所有 SQL 测试缺少 TAP plan 而报告零测试。应恢复数据库测试入口，并增加正常删除、两类引用、双会话竞争、历史保留、Vault 清理失败和错误脱敏用例。
