# V4 默认能力策略指标说明

这份文档用通俗语言解释管理端“默认能力策略”页面里的每一项内容。

## 1. 先理解“默认能力策略”

默认能力策略可以理解为：**一次 AI 代码评审任务的能力清单和资源上限**。

用户点击“开始 AI 分析”时，系统会生成一份任务策略快照，并固定到本次任务中。之后即使管理员调整运行配置，已经创建的任务仍然使用创建时的策略，避免任务执行到一半规则发生变化。

需要注意：

- 页面是只读的，不是让用户逐项开关能力的配置页面。
- 这些能力属于平台统一能力，接入任何模型都默认具备。
- Agent 实际能做什么，还会受到角色权限、剩余预算、沙箱、网络白名单等限制。
- 页面上的数值是平台统一的初始默认值。

### 配置从哪里读取

当前能力清单、Harness 版本、工具权限和默认策略只在下面这个 Manifest 中人工维护：

`worker/harness/code-review-acp/v4-capability-contract.json`

Worker 直接读取其中的 `defaultPolicy`；数据库保存由该 Manifest 生成的版本化部署副本；管理页面读取数据库当前激活版本。升级 DeepSeek Harness 的完整步骤见同目录的 `README.md`。

## 2. 怎么看这些指标

可以先记住下面四条：

1. **能力开关**决定 AI 有没有某一类能力。
2. **数量和时间上限**越大，AI 可执行的工作通常越多，但耗时和资源消耗也可能越高。
3. **并发上限**越大，任务可能越快，但会占用更多 CPU、内存和模型并发额度。
4. **安全项**不是性能参数，例如“完全访问关闭”“禁止私有网络”应保持安全状态。

一次任务在达到某个局部上限前，也可能先达到总请求数、运行时长或其他上限而停止。

| 页面指标 | 初始默认值 | 含义 |
|---|---:|---|

## 4. 20 个能力开关

绿色“✓”表示该能力已进入默认策略，红色“✕”表示不可使用。能力开启不代表所有 Agent 都拥有该能力，系统还会按照 Agent 角色进一步收窄权限。

| 能力 | 通俗解释 |
|---|---|
| 系统指令（`instructions`） | 允许加载平台提供的工作要求和安全规则，告诉 Agent 应该如何进行代码评审。 |
| Skills（`skills`） | 允许加载平台认可的专业技能，例如需求分析、后端、前端、测试和安全评审方法。 |
| 目标 Goal（`goal`） | 允许创建、读取和更新本次评审的总体目标，减少执行过程中偏离任务。 |
| 计划 Plan（`plan`） | 允许 Agent 先规划再执行，把复杂评审拆成可管理的步骤。 |
| 待办 Todo（`todo`） | 允许维护任务清单和完成状态，帮助跟踪还有哪些内容没检查。 |
| Ralph 循环（`ralph`） | 允许进行“检查结果—发现不足—继续补查”的迭代循环，适合复杂问题；循环次数受“Ralph 轮次上限”约束。 |
| 子 Agent 派生（`subagentSpawn`） | 允许创建一个使用新上下文的子 Agent，把独立调查任务委派出去，例如单独检查测试或安全问题。 |
| 子 Agent 分叉（`subagentFork`） | 允许基于父 Agent 已有的对话和分析历史分出子 Agent，适合沿着当前线索继续深入。 |
| 子 Agent 控制（`subagentControl`） | 允许查看子 Agent、向其发送消息或中断它，便于协调多个并行任务。 |
| 工作流（`workflow`） | 允许把多个步骤编排成工作流，并按规则串行或并行执行。 |
| 后台 Jobs（`jobs`） | 允许管理耗时较长的后台任务，例如构建、静态检查或测试，并查看任务状态和输出。 |
| Shell（`shell`） | 允许在隔离沙箱中运行命令，例如执行测试或构建；不代表拥有宿主机完全权限。 |
| 文件系统（`filesystem`） | 允许读取、搜索以及在隔离工作区内写入文件；原始固定代码快照仍受保护。 |
| Web 搜索（`webSearch`） | 允许搜索互联网资料，但实际访问仍受域名白名单、端口和请求次数限制。 |
| Web 抓取（`webFetch`） | 允许读取指定网页内容，同样受 Web 安全策略限制。 |
| 并行工具（`parallelTools`） | 允许在同一步中并行调用多个安全工具，以缩短分析时间；修改类工具仍强制串行。 |
| 自动压缩（`autoCompaction`） | 当上下文过长时，允许把早期内容压缩成摘要，腾出上下文空间继续工作；压缩会占用独立请求预算。 |
| Session 持久化（`sessionPersistence`） | 允许保存执行会话、事件和检查点，支持审计以及异常后的恢复。 |
| Session 恢复（`sessionResume`） | Worker 重启或任务中断后，允许从可恢复的会话继续，而不是完全从头开始。 |
| Artifacts（`artifacts`） | 允许保存评审过程产生的成果，例如报告、证据、补丁或其他结构化输出。 |

## 5. Sandbox 沙箱

沙箱用于限制 Shell、文件写入和进程活动的范围，防止评审任务直接影响宿主机或其他任务。

| 页面指标 | 初始默认值 | 含义 | 调大或改变后的影响 |
|---|---:|---|---|
| 默认模式 | `workspace-write` | Agent 可以读取固定代码快照，并在本次任务的隔离工作区中写文件。 | 改成 `read-only` 后更安全，但无法完成需要写文件的操作。 |
| 完全访问 | 关闭 | `danger-full-access` 不可用，Agent 不能绕过沙箱直接获得完整系统访问权。 | 这是强制安全项，系统固定为关闭。 |
| 命令超时 | 60,000 ms（60 秒） | 单条沙箱命令最多允许运行多久，超时后会被终止。 | 越大越适合慢命令，但卡住时会等待更久。 |
| 每次尝试最大进程数 | 64 | 一次 attempt 最多允许存在的进程数量，用来防止进程无限创建。 | 越大可运行更多并行命令，但 CPU 和内存压力更高。 |
| 工作区最大字节 | 2,147,483,648 字节（2 GiB） | 本次尝试的可写隔离工作区最多占用多少存储空间。 | 越大可容纳更多构建产物，也会占用更多磁盘。 |
| 工作区最大文件数 | 100,000 | 隔离工作区最多可以包含多少个文件。 | 越大越能支持大型依赖或构建输出，但文件扫描和清理成本更高。 |

> `attempt` 可以理解为一次任务执行尝试。失败后重试通常会产生新的 attempt。

## 6. Agent Tree 上限

根 Agent 可以把工作委派给子 Agent，形成一棵 Agent Tree。这组指标控制团队规模和委派层级。

| 页面指标 | 初始默认值 | 含义 | 调大后的影响 |
|---|---:|---|---|
| 每次尝试最大 Agent 数 | 8 | 一次 attempt 中根 Agent 和所有子 Agent 的总数上限。 | 可拆分更多任务，但模型请求和资源消耗通常更高。 |
| 最大委派深度 | 2 | 子 Agent 最多可以继续向下委派多少层；根 Agent 深度为 0。 | 层级更深可处理复杂分工，但更难控制和汇总。 |
| 最大并发子 Agent | 4 | 同一时间最多允许运行多少个子 Agent。它限制同时运行数，不是累计创建数。 | 可能更快，但模型并发、CPU 和内存压力更高。 |
| 允许进程外 Provider | 否 | 是否允许通过独立外部进程运行其他 Agent Provider。V4 首版只使用 Harness 原生的进程内子 Agent。 | 这是安全边界，系统固定为否。 |

示例：最大 Agent 数为 8、最大并发子 Agent 为 4，表示一次尝试累计最多有 8 个 Agent，但同一时刻最多运行 4 个子 Agent。

## 7. 分层模型预算

这里的“请求”主要指向大模型发起的一次调用，不等于工具调用，也不等于一条聊天消息。预算用于控制成本并避免 Agent 无限循环。

| 页面指标 | 初始默认值 | 计数口径与含义 |
|---|---:|---|
| 总请求上限 | 160 | 一次 attempt 内所有模型请求合计的硬上限。任何分类预算都不能突破它。 |
| 根 Agent 请求上限 | 80 | 根 Agent 普通分析请求的累计上限。 |
| 子 Agent 请求上限 | 32 | **每个子 Agent 各自**最多可使用的普通分析请求数，不是所有子 Agent 共同分 32 次。所有请求仍同时受总请求上限约束。 |
| 重试请求上限 | 12 | 因临时错误等原因重新请求模型的累计上限，防止持续重试。 |
| 压缩请求上限 | 8 | 自动压缩上下文时可使用的模型请求累计上限。 |
| Ralph 轮次上限 | 12 | Ralph 补查循环最多进行的轮次数，防止“检查—补查”无限重复。 |

这些上限不是相加后必然可以全部用满。例如总请求上限为 160 时，即使各局部预算还有剩余，累计达到 160 后也不能继续请求模型。

## 8. 并行工具、工作流和 Jobs

| 页面指标 | 初始默认值 | 含义 | 调大后的影响 |
|---|---:|---|---|
| 每步最大并行工具数 | 8 | Agent 在一个执行步骤中最多同时调用多少个可安全并行的工具。 | 查询可能更快，但瞬时资源消耗更高。 |
| 变更类工具串行 | 是 | 写文件、修改状态、提交结果等有副作用的工具一次只执行一个，避免并发冲突。 | 这是强制安全项，系统固定为是。 |
| 工作流最大并发步骤 | 4 | 一个工作流同时最多执行多少个步骤。 | 工作流可能更快，但资源和模型并发消耗更高。 |
| 工作流最大运行时长 | 900,000 ms（15 分钟） | 单个工作流最多运行多久，超时后停止。 | 越大越适合复杂流程，但异常流程会占用资源更久。 |
| 每 Owner 最大并发 Job | 4 | 同一个任务拥有者（通常是发起 Job 的 Agent）同时最多运行多少个后台 Job。 | 可同时跑更多构建或检查，但 CPU、内存压力更高。 |
| Job 最大运行时长 | 300,000 ms（5 分钟） | 单个后台 Job 最多运行多久，超时后停止。 | 越大越适合慢测试或构建，但卡住时等待更久。 |

“并行工具”“工作流步骤”和“后台 Job”是三个不同层次的并发限制，互相不能替代。

## 9. Web egress allowlist

Web egress 指评审任务主动访问外部网络。即使 Web 搜索和抓取能力已开启，请求仍必须通过以下安全检查。

| 页面指标 | 初始默认值 | 含义 | 调大或改变后的影响 |
|---|---:|---|---|
| 每次尝试最大请求数 | 20 | 一次 attempt 最多发起多少次外部 Web 请求。 | 越大可查更多资料，也会增加耗时、流量和外部访问面。 |
| 单响应最大字节 | 2,097,152 字节（2 MiB） | 单个 Web 响应最多接收多大内容，超过上限会被拒绝或截断。 | 越大可读取大页面，但内存和上下文处理压力更高。 |
| 累计最大字节 | 20,971,520 字节（20 MiB） | 一次 attempt 所有 Web 响应内容的累计大小上限。 | 越大可下载更多内容，但流量和存储消耗更高。 |
| 允许 HTTP | 否 | 是否允许未加密的 `http://` 访问。默认只允许 HTTPS。 | 开启会增加明文传输和被篡改风险，生产环境不应开启。 |
| 允许端口 | 443 | 外部请求允许连接的目标端口；443 是标准 HTTPS 端口。 | 增加端口会扩大网络访问面，应按需配置。 |
| 允许域名 | 空 | 只允许访问明确列出的域名。**空白名单代表所有外部目标都无法访问**，不是允许任意域名。 | 增加域名后才可访问相应站点；应只加入可信且必要的域名。 |
| 禁止私有网络 | 是 | 阻止访问本机、局域网、云元数据地址和其他私有网段，降低 SSRF 风险。 | 这是重要安全项，生产环境应保持开启。 |
| 最大重定向 | 3 | 一个请求最多跟随 3 次 HTTP 重定向，超过后停止。每次跳转仍需通过安全校验。 | 越大越兼容多次跳转的网站，也增加绕转和耗时风险。 |
| 请求超时 | 20,000 ms（20 秒） | 单次 Web 请求最多等待多久。 | 越大越能容忍慢网站，但任务可能等待更久。 |

域名白名单通常应填写主机名，例如 `docs.example.com`，不填写协议、路径或空格。

## 10. Session 保留期

Session 保存 Agent 的执行事件和恢复信息，用于异常恢复与审计。

| 页面指标 | 初始默认值 | 含义 | 调大或改变后的影响 |
|---|---:|---|---|
| 每多少事件建立检查点 | 100 | 每累计 100 个 Session 事件建立一个恢复检查点。 | 数值越小，恢复点越密但写入更多；越大，写入更少但恢复时可能需要重放更多事件。 |
| 保留天数 | 7 天 | Session 数据最多保留多久，过期后可由清理机制删除。 | 越大越方便追溯，但占用更多存储并延长数据留存时间。 |
| 静态加密 | 是 | Session 数据落盘后使用静态加密保护。这里指存储加密，不等同于网络传输加密。 | 生产环境应保持开启。 |
| Worker 重启后恢复 | 是 | Worker 意外退出或重启后，允许使用有效检查点继续未完成任务。 | 关闭后中断任务通常需要重新执行。 |

## 11. 常见疑问

### 11.1 为什么能力全部开启，Web 还是可能不能用？

`webSearch` 和 `webFetch` 开启只表示 Agent 拥有工具。目标域名还必须出现在“允许域名”中；白名单为空时，所有外部访问都会被拒绝。

### 11.2 为什么 Shell 开启也不能随便操作机器？

Shell 运行在隔离沙箱中，受工作区、命令超时、进程数和角色权限限制，而且“完全访问”固定关闭。

### 11.3 为什么还没用完根 Agent 或子 Agent 预算，任务就停止了？

可能是总请求上限、工作流时长、Job 时长、取消信号、租约、沙箱资源或其他治理规则先达到上限。

### 11.4 数值越大是不是越好？

不是。更大的预算和并发通常能提高复杂任务的处理能力，但也会增加模型成本、执行时间、CPU、内存、磁盘和安全风险。应根据实际任务规模和压测结果调整。

### 11.5 页面显示的是系统永久默认值吗？

是平台当前统一的默认值。20 个能力不随接入模型变化；任务创建时会把策略冻结为快照。实际执行过程中，角色权限、剩余预算、安全规则或运维紧急熔断仍可能进一步收窄能力。

## 12. 一句话总结

默认能力策略就是：**让 AI 默认拥有完整的代码评审工具，同时用预算、沙箱、角色权限、网络白名单和保留规则限制它能用多少、能访问哪里、能运行多久。**
