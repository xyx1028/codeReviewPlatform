# 需求开发评审一致性平台 V1.51：技能ZIP跨平台打包兼容最终执行方案

## 1. 背景与目标
Mac Finder 压缩生成的 `__MACOSX`、AppleDouble、`.DS_Store` 被路径白名单拒绝；压缩整个技能目录时根入口缺失。让管理员可直接上传 Mac / Windows 普通 ZIP，无需手工清理。

## 2. 范围与非目标
兼容根入口和唯一一层外部目录；忽略 Mac 元数据及 Windows `Thumbs.db`、`desktop.ini`。业务文件仍遵守现有路径、扩展名、UTF-8 和容量限制。暂不支持任意深层入口、多个技能混装、中文业务路径、反斜杠路径、加密 ZIP、ZIP64。

## 3. 当前实现与问题
浏览器预填 `src/lib/skill-bundle-preview.ts`；Edge `skill-bundle-admin/bundle.ts` 权威校验并发布原始 ZIP；Worker `zip-archive.ts` 独立验证、缓存、物化。Edge 的差异比较还会重新读 ZIP。只修前端会导致 Worker 复核失败。

## 4. 验收标准
- 根结构与单层文件夹结构均支持预填、检测、发布、Worker 校验和读取。
- 元数据不进入文件树、bundle hash、缓存或运行时目录；原始 ZIP 的 archive hash 保持按原始字节计算。
- 仅当全部有效条目属于同一外层目录且该目录直接包含 SKILL.md 时移除前缀。
- 路径穿越、绝对路径、符号链接、非法业务文件、重复和大小写冲突继续拒绝。
- 旧有合规包的 manifest 和三层 hash 不变。

## 5. 总体设计
两侧独立实现相同映射：校验原始条目安全性 → 排除有限名单的打包元数据 → 判定唯一外层目录 → 严格校验业务路径 → 构造规范 manifest。原 ZIP 不改写。中央目录最多 800 个原始条目（原 200 上限的四倍余量），过滤后有效条目（含目录）的 200 上限保持不变；忽略条目不解压、不执行，其压缩字节仍受整包 10 MiB 上限约束。浏览器仅预填，不成为权威校验器。

## 6. 数据与接口
不涉及数据库结构、迁移、RLS 或 RPC 改动；manifest 格式与原始归档存储不变。

## 7. 前端与运行时
浏览器识别同一入口结构并显示兼容提示。Worker 从规范相对路径物化；AI 优化和 Edge 差异比较复用各自的相同路径映射。

## 8. 安全、兼容与回滚
危险路径不能因元数据名而绕过检查，元数据中的加密或特殊文件也拒绝。新包应在 Edge 和 Worker 一起更新后发布；旧 Worker 不认识新包装形式。已发布的新包回滚前须重新打成旧版根结构，不能直接只回滚 Worker。保留原包用于诊断，不触碰云端数据。

## 9. 实施步骤与文件范围
Edge bundle.ts、Worker zip-archive.ts / skill-paths.ts / bundle-validator.ts、浏览器预填与上传提示；补充两侧等价性、安全回归、预填与真实打包样本验证；同步版本展示。

## 10. 验证结果
已完成路径兼容、前端提示、Edge 差异读取与 Worker 解包改造。验证结果：

- 针对性回归 168 项通过，包含 Mac / Windows 包装、根入口、元数据过滤、数量上限、差异读取、危险路径/符号链接/加密包、重复与大小写冲突、完整技能树物化。
- Worker 全量测试 1084 passed、35 skipped；之后新增的 2 项物化测试已在针对性回归通过。跳过的是已有可选集成测试，未宣称通过。
- 前端全量测试 261 passed；`worker:typecheck`、`worker:build`、`web:typecheck`、`build` 通过。
- `lint` 通过（已有 11 条警告）；构建仍有已有 chunk 体积提示。
- 两个真实原始 ZIP：kwork-skill-engineering（12 文件）、mcp-hub-engineering（13 文件），均通过 Edge / Worker manifest 等价、缓存与 DSH 物化验证。未修改原包，测试不依赖把用户 ZIP 提交进仓库。
- 重建本地 Worker 镜像，两个真实原包均在 Linux Docker 容器内通过解包、缓存、物化验证；本地 PostgreSQL `skill_bundle_hash` 与 Worker 计算一致。
- 本地 Supabase 可查询，但真实 API POST 出现 `UND_ERR_SOCKET`，curl POST 返回非 Supabase 的 `@error=resource not found`；HTTP 上传/发布烟测未完成，未确定拦截来源。启动的本地 Worker 同样出现 RPC fetch failed，已停止本次新建的验证 Worker；本次启动的 functions serve 也已停止。未改云端或 Linux 服务。
- 版本展示同步 V1.51，一致性校验通过；不新增数据库迁移。

## 11. 用户手动发布与验收
1. 用户检查并提交代码（不要把测试用 ZIP 和本机 .env 一并提交），推送 GitLab release，再由现有流水线构建统一应用镜像。
2. 公司 Linux 执行现有 `deploy/supabase-selfhost/scripts/release.sh --dry-run`，确认后 `--apply`；该脚本复制整个 Function 目录，包含 bundle.ts，并更新 Worker / Web。本次没有新增外部依赖，不需要重建 edge-runtime 基础镜像。
3. 后续 V1.52 已将统一发布默认改为 4 个 Worker，每个并发 2 条任务，发布后无需额外扩容。
4. 在 Linux 平台新增或更新一个技能，直接使用 Mac Finder 或 Windows 压缩的普通 ZIP；确认预填、检测文件树、发布和新评审的技能加载均成功；对已缺失的历史 Storage 文件，本次兼容改造不会自动补齐。
5. 任一步出现 API/存储故障按日志另查；不能把本地解析通过当作线上已发布。
