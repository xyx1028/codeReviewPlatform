# 需求开发评审一致性平台 V1.58：Linky项目组预置清单最终执行方案

## 1. 背景与目标
上游跨组查询先汇总再分页，Mac 实测全组第一页 20 条需 18.23 秒，超过浏览器 15 秒限制；按“工具开发组”取完 273 条只需 5.19 秒。用户不一定记得完整项目组名称，因此要求将接口中实际查到的项目组预置到下拉框，后续人工维护，等上游提供合适接口后再替换。

## 2. 范围与非目标
为看板、批次导入及列表表头的共享项目组选择器提供本地预置目录；未选组不发故事或候选跨组请求，选组后继续原有按组取数和分页。保留手工输入完整名称查询。无定时同步、后台任务、数据库、Worker、MCP 或上游修改；不增加管理页面。

## 3. 当前实现与问题
`src/components/linky/LinkyStoryPicker.tsx` 的看板默认查询全组；导入页依赖跨组第一页生成候选，候选既慢又不完整。`workspace-options.ts` 只合并已加载页和已选名称，首次进入缺少可选组。

## 4. 需求与验收标准
- 预置名称必须来自真实接口结果，记录采集时间和范围；不把 scopes 数值当名称，也不编造空组。
- 进入看板／导入页立即可搜、可选预置项目组，不等待接口。
- 未选组、清除组后不查询全组；初始已有组时仍直接读取该组。
- 选定组后请求仅携带该完整名称；看板按页请求，导入继续维持既有勾选集合与单组边界。
- 可通过编辑单独 TypeScript 名称清单新增／删除项目组，随后构建发布；当前会话也可输入未预置的完整组名。
- 预置、运行时名称和已选名称去重合并；下拉支持部分名称搜索。

## 5. 总体设计
一次性从已公开的只读 stories 接口分页收集 workspace_id/name，最多四个请求并行；仅保存去重项目组，不保存故事正文。将真实名称写入本地常量文件，运行时与当前组响应中的名称合并。共享选择器先展示目录门禁，选组后开启 storiesQuery，不再执行 workspaceCatalogQuery。

## 6. 数据与接口设计
新增 `src/components/linky/workspace-presets.ts` 名称数组，作为临时人工维护目录。沿用现有 GET `/stories?workspace_name=...&page=...&page_size=...`，不新增 token、RPC 或数据库。无故事的启用工作区可能无法从故事列表发现；清单只代表采集时可观察到的组。

## 7. 前端与 Worker/运行时改造
调整 `LinkyStoryPicker.tsx` 首屏与查询启用条件，沿用现有选择框及门禁布局；看板提示“先选组再浏览”，导入保留单组导入说明。预置合并集中在 `workspace-options.ts`，不依赖上游候选查询。Worker/MCP 不涉及。

## 8. 安全、兼容与回滚
只有项目组名称公开进入前端，不包含成员、凭据或故事内容。用户输入继续作为 workspace_name 参数编码，不能改变 API host。初始批次组、选组清空历史勾选、锁定已导入项保持现有行为。可回退前端镜像；本轮无数据迁移。停止默认跨组浏览是本次为规避上游慢查询而实施的临时范围收敛。

## 9. 实施步骤与文件范围
1. 只读采集真实项目组并说明发现范围。
2. 加入人工清单、合并候选，移除首屏跨组请求。
3. 验证选择／查询边界、测试、类型检查和构建。
4. 同步产品版本 V1.58、线上技能及手工发布说明。

主要文件：`workspace-presets.ts`、`workspace-options.ts` 及测试、`LinkyStoryPicker.tsx`、`src/lib/product-version.ts`、本方案和线上技能参考。

- `npm run web:typecheck`、`npm run build` 和 `git diff --check` 通过；构建只有既有大包提示。
- `npm run test:web`：24 个文件、272 项通过，涵盖预置候选、未收录完整名称、去重、已选组保留及既有取数／勾选边界。
- `npm run version:check -- <本方案>` 通过：文档和产品展示均为 V1.58。
- 本地浏览器使用真实组件与模拟需求响应检查：看板及导入页首次打开请求数为 0；输入“工具”可找到预置完整名称；选中后只请求该组；看板翻到第二页保留 workspace_name，清除组后回到门禁且请求数不增加；导入模式逐页读取仍携带同一个组，已有初始组可直接加载。
