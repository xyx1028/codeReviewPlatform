# 需求开发评审一致性平台 V1.40：需求附件可读化最终执行方案

## 1. 背景与目标

Linky 导入会冻结 PDF、Office 和图片等附件的存储路径与 SHA256。当前 Worker 只把原始字节写入 attempt workspace，提示 Agent 使用 DSH 的 `read / grep` 阅读全部附件；二进制文件实际不能按文本读取，可能漏掉 PRD 验收口径。本次为有文本层的常见附件生成受控文本视图，让评审能引用真实需求内容，并明确报告无法提取的附件。

## 2. 范围与非目标

- 支持 PDF 文本层及 DOCX、XLSX、PPTX 的文本提取；保留原始附件及 SHA 校验。
- 在提示词和需求快照中列出可读视图与提取失败状态。
- 同步修复宿主机模型代理的 DNS 目标校验与两个过期真实进程测试夹具。
- 本次不做 OCR，不修改冻结的数据库附件记录，不允许从外部 Office/PDF 文本执行指令。
- 不把 DSH `0.2.0-rc.2` 直接替换当前 ACP 运行时。新版本的 Office 转 PDF 服务挂在 Web bundle，不在当前 ACP base profile；它产出 PDF 而非可供 `read / grep` 使用的文本。新 base 同时把 workflow holder 改为 `workflow-ptc`、默认禁用 `tool-ralph`，并引入 Session V4。直接升版会改变冻结能力契约和恢复兼容键，必须另作版本迁移和任务切换验证。

## 3. 当前实现与问题

- `worker/src/ai/requirements/attachment-materializer.ts` 从冻结的 `requirement_context.attachments` 下载并校验 SHA256，然后只写原件。
- `worker/src/ai/prompts/agent-review-v1.ts` 指示 Agent 用 `read / grep` 读所有附件；DSH 文件读取插件对二进制拒绝或只能看到乱码。
- `scripts/model-vpn-proxy.mjs` 仅按主机名文字过滤，HTTP 和 CONNECT 在过滤后才执行 DNS 解析，可由 DNS 别名绕过 loopback/元数据边界。
- 两个 opt-in 真实 DSH 测试使用旧 Broker 响应或旧提交参数，未验证当前契约。

## 4. 需求与验收标准

1. 原件 SHA 不符不得生成任何可读视图；原件取不到时继续计入缺失。
2. 可提取附件的文本视图位于同一 attempt workspace，包含原件路径和明确的截断/提取边界；单个压缩原件不超过 8 MiB，ZIP 展开不超过 24 MiB，文本输出不超过 100000 字符，PDF 最多检查前 100 页。
3. 无法提取或无文本层时，提示词明确说明缺失的内容，不把附件列为“已读全文”。Agent 应按不确定性处理结论。
4. 代理对 DNS 解析出的全部候选地址做限制，并连接已校验的地址，HTTP Host/TLS SNI 仍保持原始域名；合法内网模型地址可以使用。
5. 相关单测、Worker 类型检查/构建、真实 DSH 测试、本地 Worker 业务链路按实际可执行范围验证。

## 5. 总体设计

冻结附件 SHA 校验 → 原件落盘 → 按扩展名提取有界文本 → 写同目录文本视图 → 需求快照和 Agent 提示词指向文本视图。提取失败仅影响该附件的内容可用性，不能被解释成已阅读。代理分支统一“解析、校验、固定连接目标”的地址策略。

## 6. 数据与接口设计

- 数据库、RPC、前端 API：不涉及。
- Worker 内部的附件物化结果增加 `readablePath`、`extractionStatus`、`textTruncated`，供快照和提示词使用。
- 不新增跨进程 DSH 工具或能力契约项。

## 7. 前端与 Worker/运行时改造

- 前端不改。Worker 在冻结附件物化阶段提取文本，原始内容仍按不可信需求资料处理。
- DSH Agent 优先读文本视图，原件仅作为溯源；没有文本视图的二进制不要求用文本工具“读完”。DOC/XLS/PPT 旧格式、图片、扫描 PDF 明确标为不可读。提取成功也只代表文本层，不代表图片、图形和批注已被读取。
- 现有 DSH Session、预算和权限边界不因附件可读化而放宽。

## 8. 安全、兼容与回滚

- 解析受单文件大小、展开大小、输出字符数限制；内容仅进入 attempt workspace，不写回冻结对象。
- 文本视图属于外部资料，不可指挥 Agent；原件 SHA 始终先验证。
- 在途任务继续使用其已冻结输入；回滚 Worker 即恢复原物化行为。代理服务更新需在宿主机服务重启后生效。
