# 需求开发评审一致性平台 V1.22：分页规范化最终执行方案

## 1. 背景与目标
当前各列表的分页配置不一致：账号列表依赖 Ant Design 隐式默认值，Git 身份列表明确设为每页 20 条并显示页大小切换器，技能证据的两个小表格每页 5 条。管理员在相邻页签间切换时看到不同的每页条数和分页控件，缺少统一预期。

本次目标是让平台内所有**启用分页**的列表首次展示均为每页 10 条；明确关闭分页的运行摘要、嵌入式明细表维持不分页。与此同时修复 Git 身份表格固定右侧“操作”列中“新增邮箱 / 编辑”贴合、裁切的问题。

## 2. 范围与非目标
### 包含
- 将 Git 身份列表从 20 条/页统一为 10 条/页，并取消与账号列表不一致的页大小切换器。
- 将技能证据弹层内两个小表格的分页阈值与页大小从 5 统一为 10。
- 显式声明账号列表为 10 条/页，避免依赖组件库隐式默认值。
- 复核全部现有分页配置，保留其他已为 10 条/页的初始化值。
- 增大 Git 身份固定操作列宽度、恢复操作间距，并将横向滚动宽度覆盖所有定义列。

### 不包含
- 不新增服务端分页 API、数据库结构、RPC、RLS 或 Worker 行为。
- 不为当前明确 `pagination={false}` 的摘要/明细表强行添加分页。
- 不改变用户已在当前会话主动选择的页码或筛选结果。

## 3. 当前实现与问题
- `src/App.tsx`：账号列表未传入 `pagination`，当前依赖 Ant Design 的默认值；冻结需求、任务、评审和操作日志已使用 10 条作为默认值。
- `src/pages/GitIdentityManagementPage.tsx`：分页设置为 `pageSize: 20` 并开启 `showSizeChanger`；操作列宽度 150、`Space size={0}`，而 `scroll.x` 为 1050，低于全部列宽总和，固定右列发生拥挤。
- `src/pages/SkillManagementPage.tsx`：技能证据中的“评审批次”和“抽样评审结论”两个表在超过 5 条时分页且每页 5 条。
- `src/components/monitoring/RuntimeAnalysisScopeCard.tsx`、`src/components/linky/LinkyStoryPicker.tsx`、`src/components/attribution-rules/RuleVisualEditor.tsx` 及其余已启用分页的列表已使用或初始化为 10 条，本次仅保持其当前语义。

## 4. 需求与验收标准
1. 所有启用分页的列表首次展示为 10 条/页，并统一显示页大小选择器，支持选择 10、20、50、100 条/页；技能证据小表格在数据不超过 10 条时不显示分页。
2. 账号列表与 Git 身份列表都以 10 条/页首次展示，并提供相同的页大小选择器。
3. Git 身份“新增邮箱”和“编辑”操作在固定右列内同一行完整可见，操作间留有可辨识间隔；横向滚动不会压缩该列。
4. 明确配置为不分页的表格保持现有展示和数据加载行为。
5. 前端类型检查和生产构建通过。

## 5. 总体设计
```mermaid
flowchart LR
  A[各页面 Table / List] --> B{启用分页?}
  B -- 否 --> C[保持 pagination=false]
  B -- 是 --> D[首屏 pageSize = 10]
  D --> E[页面保留各自的总数、筛选与服务端换页逻辑]
```

前端不引入新的后端分页协议。对当前已有分页组件，仅统一其初始化页大小；受控分页继续由所属页面的状态和回调维护。Git 身份表格将以列宽总和作为横向滚动下限，并为固定操作列预留按钮间距。

## 6. 数据与接口设计
不涉及数据库表、迁移、RPC、Storage、类型协议或外部接口变更。现有列表仍一次性或按原有服务端接口读取数据。

## 7. 前端与运行时改造
已完成以下前端修改：
- `src/App.tsx`：账号列表显式使用 `pageSize: 10` 与 `showSizeChanger: false`，不再依赖组件库隐式默认值。
- `src/pages/GitIdentityManagementPage.tsx`：分页改为 `pageSize: 10` 与 `showSizeChanger: false`；“操作”固定列由 150 扩至 180，两个链接使用 `Space size="small"` 和 `wrap={false}`；横向滚动宽度按全部定义列宽合计更新为 1410。
- `src/pages/SkillManagementPage.tsx`：技能证据中的“评审批次”和“抽样评审结论”表格改为数据超过 10 条才分页，且每页 10 条。
- 复核 `src` 内其余分页配置：运行范围、Linky、需求/任务、技能、日志和归属规则的首次页大小均为 10；明确 `pagination={false}` 的实时摘要、嵌入式明细表保持不分页。

Worker、DSH、权限、预算、Session、数据库和 API 均未改动。

## 8. 安全、兼容与回滚
本次仅改变浏览器端首屏展示条数和列布局，不触及权限、密钥、服务端数据或审计记录。历史数据和在途分析任务不受影响。

回滚方式为还原本次三个前端文件及本执行方案；无需数据回滚或服务重启。

## 9. 实施步骤与文件范围
已按以下顺序实施：
1. 盘点所有 `Table` / `List` 的分页配置，确认仅 Git 身份和两个技能证据小表格不符合 10 条默认值。
2. 为账号列表补充显式分页，避免隐式默认；同步修正 Git 身份分页和操作固定列布局。
3. 将两处技能证据小表格的分页阈值、页大小从 5 统一到 10。
4. 用静态检索确认 `src` 中不存在 5、20 或更大的 `pageSize` / `defaultPageSize` 默认值，并完成生产构建。
