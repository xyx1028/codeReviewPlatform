# 需求开发评审一致性平台 V1.45：验收点风险项页签分页最终执行方案

## 1. 背景与目标
V1.44 已将验收点评审改为可分页的三列概览与详情弹窗，但风险项仍在验收点表格下方完整展开。验收点和风险项混排会拉长阅读路径；验收点分页固定为每页 10 条，不能按实际审阅密度调整。

V1.45 将结构化评审内容拆分为“验收点”和“风险项”两个页签，并让两个列表各自提供与技能列表一致的每页条数选择。两类内容均采用紧凑的概览列表与按需查看详情，方便用户聚焦结论和风险。

## 2. 范围与非目标
- 包含：验收点/风险项页签、页签数量、两个列表独立的客户端分页状态、每页 10/20/50/100 条选择、范围说明、验收点与风险项概览的单行省略和悬停全文提示、两个详情弹窗、响应式分页布局和组件测试。
- 保留：验收点详情弹窗、代码证据固定每页 2 条、历史报告降级、既有结论及分歧文案。
- 不包含：数据库、RLS、RPC、Edge Function、Worker、评审 JSONB 契约、服务端分页、分页设置持久化或重新分析。

## 3. 当前实现与问题
`src/components/AcceptanceReviewCard.tsx` 对已加载的 `acceptance_review.criteria` 和 `risks` 在浏览器端切片。V1.44 的验收点为固定每页 10 条的概览表，而风险项是逐项展开的卡片；风险多时占用大量垂直空间。`src/pages/SkillManagementPage.tsx` 的技能列表使用 Ant Design `pageSize: 10`、`showSizeChanger: true` 和 `[10, 20, 50, 100]`，作为本次分页体验的参照。

## 4. 需求与验收标准
1. 版本 1 的结构化评审以“验收点”和“风险项”两个页签展示，页签显示各自总数；默认打开验收点。
2. 验收点页签继续展示三列概览、点击/键盘打开详情弹窗。
3. 风险项页签以三列概览展示“风险项、确认程度、影响”；点击或键盘操作任一行打开风险详情弹窗。
4. 风险详情完整展示确认程度、归因、触发条件、影响、关联验收点、复核说明和代码依据。
5. 验收点和风险项均在浏览器端独立分页，默认每页 10 条；分页器可选择 10、20、50、100 条，与技能列表配置一致。
6. 改变某个页签的页码或每页条数不得影响另一页签；改变条数后该页签回到第 1 页，报告切换后两个列表回到第 1 页。
7. 分页范围准确反映当前列表；列表有内容时可调整每页条数，空列表显示已有的明确空态。
8. 桌面端两类概览表的长文本均单行截断；鼠标悬停单元格可查看完整文本，点击行仍打开对应详情弹窗。
9. 历史报告降级、证据的两条固定分页及数据契约保持不变；管理员“查看当前版本”显示 `V1.45`，文档版本与产品版本校验通过。

## 5. 总体设计
卡片维持现有紫蓝色信息层级，页签只承担内容域切换，不复制数据。每个页签拥有独立的 `{ currentPage, pageSize }`，避免用户在风险列表翻页时改变验收点阅读位置。两种概览表均为单行可点击行，完整信息在悬停提示或详情弹窗中按需呈现。

```mermaid
flowchart TD
  R[acceptance_review JSONB] --> T{活动页签}
  T --> C[验收点：三列概览与详情弹窗]
  T --> K[风险项：三列概览与详情弹窗]
  C --> CP[独立分页：10/20/50/100]
  K --> KP[独立分页：10/20/50/100]
  C --> E[代码证据：固定每页 2 条]
  K --> E
```

## 6. 数据与接口设计
不涉及数据库、迁移、RPC、RLS、Storage、Edge Function 或 Worker。

复用 `AcceptanceReviewReport.criteria`、`findings`、`risks`、`sources` 与 `AiCodeEvidence`。分页只对浏览器已取得的数组切片，无新增请求、写入或持久化。

## 8. 安全、兼容与回滚
- 模型文本继续作为 React 文本节点显示，不解释为 HTML 或脚本。
- 弹窗不引入写操作、权限变化或额外数据暴露；仍只展示当前页面已取得的评审结果和关联证据。
