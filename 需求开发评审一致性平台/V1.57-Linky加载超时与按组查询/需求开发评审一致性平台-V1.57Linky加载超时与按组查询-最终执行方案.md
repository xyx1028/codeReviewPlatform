# 需求开发评审一致性平台 V1.57：Linky加载超时与按组查询最终执行方案

## 1. 背景与目标
线上新 Linky 域名已部署，但用户故事页持续加载。2026-10-20 实测跨项目列表第 1、2 页均超过 25 秒未响应；指定“工具开发组”约 0.7 秒返回 200、273 条总数。线上前端资源已包含新地址，运行时未覆盖旧地址。

## 2. 范围与非目标
按用户后续要求，用户故事看板改为真实接口分页，补浏览器请求超时和项目组名称直接查询。导入页保持按组加载与勾选逻辑，避免分页改动丢失已有选择。此次不修改上游服务、Worker、数据库、MCP、网络或凭据，不以本地测试替代线上业务验证。

## 3. 当前实现与问题
`src/lib/linky-live.ts` 一次串行拉最多 12 页、每页 200 条，等待结束才返回，fetch 没有超时。`LinkyStoryPicker.tsx` 的项目组候选也依赖跨组查询，用户不能在汇总接口慢时直接指定项目组；候选加载失败还可能遮盖已成功的单组查询。

## 4. 需求与验收标准
- 单次请求含响应体解析有 15 秒超时，失败可见，不无限转圈；取消页面查询与超时分类分开。
- 看板和导入页均可直接输入完整项目组名称并选择查询，不等待全量候选成功。
- 选定项目组后只由该组查询的加载和错误控制列表，不被跨组候选错误阻断。
- 看板首屏和每次翻页只请求对应一页，页码、每页大小、项目组、负责人进入查询键；使用上游 total，不一次获取 12 页。切组、负责人和每页大小回第一页。
- 保留全部项目组范围；输入值只作为 workspace_name 查询参数。看板候选从已加载页提取，可手填，不能额外依赖全量后台拉取。
- 上游只支持项目组和负责人远程筛选；编号／标题、状态、发布窗口明确为当前页筛选，不能冒充全局过滤。导入页仍用既有单组勾选边界，触及分页安全上限时提示结果不完整。

## 5. 总体设计
请求层 AbortController 统一管理超时、外部取消及清理。单页读取与既有按组汇总读取分开，前者用于看板。共享项目组选择控件保留服务返回选项，并加入用户输入的完整名称候选；列表上方提供入口。看板不额外拉全量候选，导入页未选项目组时只读一页候选；手动选组即可独立读取组内数据。达到导入分页安全上限时显示范围提示，用户可缩小到单组。

## 6. 数据与接口设计
无数据库、RPC 或接口契约变更，继续 GET `/stories?workspace_name=...&page=...&page_size=200`，不增加 token。客户端错误类型增加 TIMEOUT。

## 7. 前端与 Worker/运行时改造
只改浏览器 Linky 客户端、项目组选择和错误展示；Worker 与 MCP 无变化。管理员展示版本同步 V1.57，不代表线上已部署。

## 8. 安全、兼容与回滚
外部取消需传递，定时器和事件监听均释放；不接受输入 host、不改变认证。保留空项目组的原有跨组语义。回滚前端镜像即可恢复原行为，Linux 网络和数据库不变。

## 9. 实施步骤与文件范围
已实现超时与取消、看板真实分页（默认每页 20 条）、项目组名称候选、错误范围和结果范围提示，并补客户端行为测试。文件包括 `src/lib/linky-live.ts`、`src/components/linky/LinkyStoryPicker.tsx`、`src/components/linky/workspace-options.ts` 及测试、`src/App.css`、产品版本及本方案。上线由用户提交、CI、Linux 统一发布完成。

- 实施前网络证据如第 1 节。只读检查线上 runtime-config 的 Linky 覆盖为空，实际 JS 包含新地址、不含旧地址；该次线上截图仍为加载状态，没有冒充已经修复。
- `npm run test:web`：24 个测试文件、272 项通过。覆盖单页只调用一次（总数 9402 时不自动追页）、项目组／负责人参数、每页 200 上限、15 秒超时、外部取消、响应体挂起，以及现有勾选范围逻辑。
- `npm run web:typecheck`、`npm run build`、`git diff --check` 通过。构建存在既有大包提示，不影响成功。
- `npm run version:check -- <本方案>` 通过，文档与管理员展示均为 V1.57。
- 未修改数据库或 Worker/MCP，未运行真实导入或评审。未提交、推送或发布新镜像；没有执行新版本的浏览器交互验收。
- 分页仅消除前端连续取多页的等待；若上游单次跨组聚合仍超过 15 秒，会提示超时，可直接输入完整项目组名称读取。上游聚合性能并未因前端修改而被证明恢复。
