# 需求开发评审一致性平台 V1.35：Agent运行详情视觉重构最终执行方案

## 1. 背景与目标
现有 Agent 运行详情正确展示了运行、用量、Agent Tree、工具、Evidence 与 Artifact 元数据，但页面将所有区域放进同质白色卡片并按数据表顺序平铺。运行状态与当前阶段缺少优先级，长哈希和表格占据了首屏视觉注意力，不能体现代码评审平台应有的精密、可信与可追溯感。

V1.35 将详情页重构为以“本次运行正在发生什么”为中心的运行指挥台：首屏先给出运行结论、当前阶段和关键运行指标；可追溯的技术元数据退居运行账本；统计、树、工具、证据和产物各自获得清晰的阅读层级，而不改变任何运行事实或权限行为。

## 2. 范围与非目标
- 包含：重构 `/batches/:batchId/agent-runs/:taskId` 对应的 `AgentRunDetailPage` 的页面结构、文案层级、视觉样式、移动端布局与键盘焦点表现。
- 包含：保留并重新编排既有运行状态、取消提醒、错误提醒、真实用量、Agent Tree、工具权限、Evidence 和 Artifact 数据。
- 不包含：修改 API/RPC、数据库、Worker、轮询频率、运行状态判定、取消权限或任一计数口径。
- 不包含：新增图表数据、模型调用、下载能力或运行控制行为。

## 3. 当前实现与问题
- `src/pages/AgentRunDetailPage.tsx` 直接以通用 `page-stack`、`Card`、`Statistic`、`Table` 顺序输出所有区域。
- 页面首屏只有标题、数个 Tag 和四个同权重统计项；“当前阶段”隐藏在概览卡底部的普通辅助文本中。
- Policy Hash / Tree Digest 与开始时间同列展示，长技术标识干扰扫描；运行账本没有与运行摘要分离。
- `src/App.css` 仅提供通用页面和 Ant Design 外观，详情页没有专属的密度、表头、状态和响应式规则。

## 4. 需求与验收标准
1. 首屏必须在无需阅读表格的情况下显示：运行状态、尝试次数、是否实时刷新、当前阶段（仅来自已有事实投影）以及关键运行时间或取消状态。
2. 页面采用“运行指挥台”信息结构：深色的状态总览带承载活动状态，静态白色内容区承载审计与明细；不使用与业务无关的装饰性渐变或泛化营销文案。
3. 概览指标、真实用量、Agent Tree、工具、证据、产物仍使用原有数据和空态，已有取消按钮及 `canManage` 门禁保持不变。
4. 长哈希仅作为可追溯账本信息展示，窄屏可换行且不能造成页面横向溢出。
5. 大屏下重点指标形成有节奏的分栏；窄屏下自动收为单列或双列，表格仍可在容器内横向浏览。
6. 键盘焦点可见；用户设置“减少动态效果”时不播放状态脉冲动画。
7. 前端类型检查和构建必须通过；版本常量与本文档版本必须一致。

## 5. 总体设计
页面采用“代码评审运行指挥台”而非普通数据面板：以深蓝石墨色的运行状态带作为唯一强视觉记忆点，强调代码评审中运行态的可信感；其余区域维持克制的浅灰蓝底、白色审计纸张和细分隔线。信息的阅读顺序为：**现在发生什么 → 此次运行规模 → 用量与可追溯账本 → 执行树和审计明细**。

```text
┌──────────────────── 运行状态带 ────────────────────┐
│ 返回 / Agent 运行详情     状态 · 尝试 · 刷新 / 取消 │
│ 当前阶段、运行起止、运行中提示        关键指标      │
└───────────────────────────────────────────────────┘
┌── 运行脉冲（Agent / 深度 / Session / 恢复） ──────┐
├── 真实用量 ───────────────┬── 运行账本 ────────────┤
├── Agent Tree ──────────────────────────────────────┤
├── 工具权限审计 ────────────────────────────────────┤
├── Evidence 摘要 ───────────────────────────────────┤
└── Artifact 摘要 ───────────────────────────────────┘
```

色彩令牌：石墨蓝 `#12233f`、深靛蓝 `#1c3f72`、审计蓝 `#3167d8`、雾蓝底 `#f3f6fb`、纸白 `#ffffff`、辅助灰蓝 `#6d7d96`、警告琥珀 `#d68a20`。字体沿用产品既有中文无衬线体系；数值使用更紧凑的字重和字距，避免新增远程字体依赖。

## 6. 数据与接口设计
不涉及数据库、类型、API/RPC、事件、配置或权限变化。页面继续调用 `getAgentRunDetail(taskId)`，复用 `AgentRunDetail` 中既有的状态、阶段、用量、树和摘要字段。运行中的“当前阶段”只使用 `attempt_phase_code` / `attempt_phase_started_at` 和 Agent 节点事实投影，绝不以计数或时间推断。

## 7. 前端与 Worker/运行时改造
- `src/pages/AgentRunDetailPage.tsx`：新增页面专属语义 class、运行状态带、脉冲指标、账本区域及按职责分组的卡片标题；保留原轮询、确认取消、表格列、空态和权限判断。
- `src/App.css`：新增 `agent-run-detail` 命名空间样式，定义状态带、指标格、账本、审计表格、响应式断点、焦点环和减少动态效果规则；不污染其他页面的通用组件样式。
- Worker、DeepSeek Harness、能力契约、Session、数据安全与 API 均不涉及。

## 8. 安全、兼容与回滚
- 前端继续只显示既有安全摘要；源码正文、Session JSONL、Storage locator、Token 和任何秘密不进入浏览器。
- `canManage` 仍是取消入口的唯一 UI 门禁，详情只读范围不扩大。
- 历史、进行中、失败、取消与封存运行均沿用原数据和状态标签；数据为空时继续使用原有空态。
- 本次为前端表现重构。若需回滚，仅回退 `AgentRunDetailPage.tsx`、`App.css` 与产品版本常量，无需数据库操作，更不会重置数据库。

## 9. 实施步骤与文件范围
1. 基于现有数据结构定义视觉令牌与“状态带—脉冲—账本—审计明细”布局。
2. 改造 `AgentRunDetailPage.tsx` 的语义结构，保持所有查询、轮询、取消与表格数据契约不变。
3. 在 `App.css` 追加详情页命名空间样式及响应式、焦点、减少动画规则。
4. 将 `src/lib/product-version.ts` 同步为 `V1.35`，执行版本一致性检查、Web 类型检查、测试和构建。
