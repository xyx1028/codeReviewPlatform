# 需求开发评审一致性平台 V1.53：内网发布操作Skill最终执行方案

## 1. 背景与目标
用户已通过统一发布脚本在公司 Linux 发布，后续新对话可能缺少脚本、路径、网络和运维上下文。将已验证流程固化为可发现的 Codex Skill，减少重复解释。

## 2. 范围与非目标
新增项目技能 crp-linux-release，记录非秘密配置、日常发布、检查和已遇故障。Mac Codex 技能目录通过符号链接指向项目正文。此次不发布应用、不登录 Linux、不改密码、不重建镜像，也不改变发布脚本行为。

## 3. 当前实现与问题
release.sh、apply-migrations.sh、worker-drain-restart.sh 已有统一编排，4×2 默认和固定网络已落地。知识分散在历史对话、README 和配置模板，部分模板仍使用 /srv/crp，真实环境为 /home/kduser/crp，不能盲目复制覆盖。

## 4. 需求与验收标准
新对话可显式使用 $crp-linux-release；能够给出正确 Linux 两阶段发布命令、解释脚本行为、定位实际配置和健康日志；区分已验证历史快照与运行时状态；正文与附件不含密钥。

## 5. 总体设计
SKILL.md 放快速入口、适用范围及授权边界；references/environment.md 放路径、服务、网络、已部署快照；references/troubleshooting.md 放锁、Functions 离线依赖、Storage 和上传拦截排查。直接调用仓库现有脚本，不复制第二份发布实现。

## 6. 数据与接口
不涉及数据库、API、迁移或新的业务配置。技能名称和 UI 元数据为 Codex 发现入口。

## 7. 前端与运行时
仅按仓库约定同步产品展示版本 V1.53；没有运行时业务逻辑改动。当前 Linux 发布版本仍以 last-release.env 和用户执行日志为准。

## 8. 安全、兼容与回滚
技能存在不授予生产写权限；已有明确授权内继续操作，不重复索要确认。没有 Linux 接入时给用户命令，不在 Mac 本机执行生产命令。只记录秘密文件路径，不读出秘密；不把旧迁移时空库不备份的决定推广到生产。保留 Linux 现有 subnet、镜像映射及 Functions 挂载修正。

## 9. 实施步骤与文件范围
创建 .codex/skills/crp-linux-release/SKILL.md、agents/openai.yaml 与两份参考；在当前 Mac 的 Codex skills 下建立单一入口；同步版本显示，执行技能规范、引用和前端检查。变更保持未提交，由用户自行提交。
