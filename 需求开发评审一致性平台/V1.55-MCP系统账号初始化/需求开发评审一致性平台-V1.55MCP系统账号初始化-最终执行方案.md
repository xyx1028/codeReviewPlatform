# 需求开发评审一致性平台 V1.55：MCP系统账号初始化最终执行方案

## 1. 背景与目标

V1.54 已把 MCP 接入统一应用镜像和 Linux 发布流程，但首次仍需手填平台账号、密码及模型。用户希望预置内部系统身份，默认模型为 `glm5.3-flash`，执行脚本即可准备 MCP。

## 2. 范围与非目标

新增 Linux 幂等初始化脚本并接入统一发布：创建 MCP 专用 Auth 账号、复用现有 REVIEWER 权限、自动生成并保存密码和调用凭证、填入默认模型并校验登录和可用模型。保留已有自定义账号和凭证。

不新增 SYSTEM 权限类型，不直接插入 `auth.users`，不把固定密码或 service-role key 写入迁移、镜像或 MCP 运行配置，不修改普通用户权限，不提交真实评审或消耗模型调用额度。

## 3. 当前实现与问题

`public.create_profile_for_new_user()` 在 Auth 账号创建时已生成 REVIEWER 资料；`can_create_review_batch()` 允许其创建批次，`can_manage_review_batch()` 限制其管理自己的批次。MCP 的普通账号登录通道已支持该权限。

`release.sh` 当前只检查已填写的 MCP 环境文件。`resolveConfiguredModel()` 只按模型 id 或展示名匹配，不能可靠地用模型管理里的 Model 值 `glm5.3-flash` 定位。

## 4. 需求与验收标准

1. 空配置或缺少配置时，正式发布自动准备 MCP 系统账号和随机凭证；重复发布不重置密码、用户 id 或访问凭证。
2. 专用账号由 Auth Admin API 创建并自动确认邮箱，应用权限仍是 REVIEWER；同名非托管账号不得被接管，管理员主动变更或禁用的托管账号不得被脚本强行恢复。
3. service-role key 只在宿主机初始化进程内使用，运行中的 MCP 仅持有 anon key 和普通账号密码；本地文件权限为 0600，日志不输出凭证。
4. dry-run 仅预览初始化计划，不创建账号、不写配置、不登录创建会话。
5. 默认模型为 `glm5.3-flash`；初始化优先按 id、唯一 model_name、展示名匹配并保存准确配置 id，兼容已有 V1.54 MCP 镜像。找不到、停用、未配置密钥或存在歧义时明确失败。
6. 初始化通过普通账号登录、自己的用户资料及只读可用模型 RPC 验证，不自动创建业务批次或提交评审。

## 5. 总体设计

release 同步 → MCP 初始化/预览 → Compose 校验 → 既有迁移/Functions 与镜像更新流程。初始化先把随机密码保存到 0600 配置，再调用账号创建 API；若创建结果不明，下次用同一密码复核，避免丢失凭证或生成重复身份。

## 6. 数据与接口设计

不新增数据库对象或 SQL 迁移。使用已有 Auth 管理接口创建并标记专用账号；使用普通账号的登录接口、`user_profile` 及 `list_enabled_model_configs` 做验证。账号标记放在管理员可写的 app_metadata，显示名只用作展示。

## 7. 前端与 Worker/运行时改造

前端与 Worker 业务逻辑不变。新增 Python 标准库实现的 Linux 初始化脚本，在宿主机把默认模型 Model 值解析成准确 id；现有 MCP 镜像无需修改即可使用。产品展示版本同步为 V1.55，页面展示随下次 CI 镜像构建更新。

## 8. 安全、兼容与回滚

初始化管理接口只允许连接明确的本机回环地址，禁止代理和跨地址重定向。账号通过服务端 app_metadata 识别，不信任用户可修改的 user_metadata。已有自定义账号不被覆盖；已有托管账号缺少本地密码时停止，不自动重置。MCP 容器不接收 service-role key。暂停 MCP 或回退镜像不删除已创建的账号及其历史批次。

## 9. 实施步骤与文件范围

新增 `deploy/supabase-selfhost/scripts/bootstrap-mcp.py` 及针对性测试；修改 `release.sh`、MCP 配置模板及发布预检测试；更新部署文档、Linux 发布 Skill 和版本常量。无需新增迁移或重建运行时依赖，Linux 拉取脚本后可使用已构建的 V1.54 应用镜像。

- Python 初始化测试 12 项通过，覆盖首次创建前先保存密码、重复执行不轮换、dry-run 不写文件或账号、创建响应丢失后恢复、同名非托管账号保护、托管密码遗失保护、管理员降权不恢复、自定义账号保留、模型唯一性与特殊字符 env 往返。
- 发布 Compose/预检与 Worker 容量测试 10 项通过；Shell 语法和 `git diff --check` 通过。
- 连接本地 Supabase 的真实 Auth Admin API 创建了随机邮箱的专用测试账号，确认 REVIEWER 用户资料、普通账号登录及可用模型 RPC；本地存在 `glm5.3-flash`，已解析到实际模型 id。重复执行保持相同身份、密码、调用凭证和配置内容。完成后删除的仅为本轮创建的测试账号。

- MCP 原有测试 67 项通过；Worker 全量测试（`--testTimeout=10000`）1093 项通过、35 项跳过；Worker 类型检查/构建、前端类型检查/构建以及 V1.55 版本一致性检查通过。
