# 需求开发评审一致性平台 V1.25：代码问答首页最终执行方案

## 1. 背景与目标
登录后的路由已默认进入 `/ask`，但无会话时仍是说明卡片，用户需要先理解左栏“新建对话”才能开始。本次将其改为以提问框为核心的代码问答工作台，视觉结构参考用户提供的开发工作台：首页中央展示欢迎语、输入区与可点击的问题示例。

## 2. 范围与非目标
- 包含：保留 `/ask` 作为登录后默认首页；重构无会话首屏；输入问题或选择示例后打开既有的仓库/分支选择弹窗；保留历史会话、消息流与证据展示。
- 不包含：不修改问答 RPC、Worker、数据库、权限、模型、会话持久化或仓库/分支固定规则。

## 3. 当前实现与问题
- `src/App.tsx` 的 `Shell` 已将 `/` 和未知已登录路由重定向到 `/ask`，导航第一项也为“代码问答”。
- `src/pages/CodeQaPage.tsx` 在没有选中会话时展示文字说明卡，页面入口不够直接；现有新建弹窗承担仓库和分支的必要选择。

## 4. 需求与验收标准
1. 已登录用户访问 `/`、`/ask` 或未知已登录路径时，最终展示代码问答页。
2. 无会话状态展示中心欢迎区、可编辑问题输入框、开始按钮和常见问题示例。
3. 输入问题后按 Enter（Shift+Enter 换行）或点击开始，及点击示例问题，均进入既有“新建对话”弹窗，并将问题带入后续对话输入区。
4. 用户仍必须选择仓库和分支，创建后不会绕过既有的服务端与前端校验。
5. 窄屏下欢迎区输入框和示例不溢出；会话与消息状态不受影响。

## 5. 总体设计
```text
登录成功 → /ask
              ├─ 有活动会话：会话标题 / 消息流 / 输入区
              └─ 无活动会话：欢迎语 → 问题输入或示例 → 选择仓库与分支 → 创建会话
```
页面以深墨色文字、低饱和蓝紫焦点色和大面积留白建立“代码探索工作台”视觉层级；只强调输入框这一主操作，不增加无关装饰卡片。

## 6. 数据与接口设计
不涉及数据库、RPC、类型、Worker、DSH、模型配置或外部接口修改。继续使用既有 `createCodeQaConversation` 与 `requestCodeQaTurn` 调用链。

## 7. 前端改造
- `src/pages/CodeQaPage.tsx`：增加欢迎态草稿与问题示例的打开入口；创建会话后现有提问输入区保留该草稿。
- `src/index.css`：仅为问答页补充欢迎工作台与响应式样式，保持消息会话态布局。
- `src/App.tsx`：现有默认 `/ask` 重定向已满足本次要求，不改动。

## 8. 安全、兼容与回滚
不改变鉴权、数据边界与服务端调用。仓库、分支必须通过原有弹窗选择，避免将任何未受控代码范围直接提交到 Worker。回滚只需恢复上述两个前端文件，不涉及数据迁移或历史会话。

## 9. 实施步骤与文件范围
1. 核对默认路由及现有问答创建流程。
2. 改造无会话欢迎工作台，将输入草稿转交给原有创建弹窗和创建后的消息输入区。
3. 增加桌面与窄屏样式。
4. 执行前端类型检查、问答纯逻辑测试和生产构建；将真实结果补入下一节。

## 11. 双区侧栏调整（V1.25.1）

用户进一步要求左侧不再并排出现两列导航：功能放在左上、历史会话放在左下，各自占可用高度约一半；项目过多时只滚动所属区域，不能挤压右侧问答内容。

实际落地如下：

```text
/ask 左栏（220px）
├─ 上半：平台功能导航（Menu，独立纵向滚动）
└─ 下半：新建对话 + 历史会话（独立纵向滚动）

右侧：代码问答欢迎页或消息流 + 输入区（单一内容区）
```

- `src/App.tsx`：仅 `/ask` 的 Sider 增加 `app-sider--code-qa`；“操作日志”子菜单的展开状态受控，进入 `/ask` 时默认收起，且仅在用户点击时展开；其他页面仍使用原导航布局。
- `src/pages/CodeQaPage.tsx`：历史会话区增加语义标题、固定的新建对话操作和可滚动会话列表；创建、选择、删除与键盘访问逻辑不变。
- `src/App.css`：上方 Menu 和下方历史会话分别限制到内容视口的一半并独立 `overflow-y: auto`；窄屏恢复为正常文档流，避免固定定位遮挡内容。
- 数据库、RPC、Worker、模型和权限边界均不涉及。

本轮验证：`npm run web:typecheck` 通过；`npm run test:web -- src/lib/__tests__/code-qa.test.ts` 通过（24/24）；`npm run build` 通过且 Harness manifest 校验通过。构建仅保留已有的单个压缩 chunk 大于 500 kB 警告。


## 12. 产品 / 评审顶层页签（V1.25.2）

### 目标
左侧导航改为两个并列的顶层页签，避免产品问答与评审管理功能混在同一个长菜单中：

```text
产品（默认 /ask）
  ├─ 代码问答
  └─ 左下：新建对话 + 历史会话

评审（默认 /batches）
  └─ 代码评审、用户故事、操作日志、个人中心及全部管理员入口
```

### 实际实现
- `src/App.tsx` 将原 `menuItems` 拆为 `productMenuItems` 与 `reviewMenuItems`；`/ask` 激活“产品”，其它业务路由激活“评审”。
- 点击“产品”导航到 `/ask`，其默认功能为代码问答；点击“评审”导航到 `/batches`，不丢弃任何原有评审、看板、日志和管理入口。
- `src/App.css` 为顶层页签提供可见的选中态；产品菜单限制在左上半区，左下保持历史会话；评审菜单在页签下占用可滚动的完整侧栏。
- 不涉及数据库、RPC、Worker、权限或模型调用改动。

### 验证结果
`npm run web:typecheck` 通过；代码问答测试 24/24 通过；`npm run build` 通过且 Harness manifest 检查通过；`npm run lint` 退出码为 0（9 条均为仓库既有警告）。

## 14. 新会话居中提问与历史归档（V1.25.4）

交互按参考图拆成两种明确状态：

```text
点击“新建对话” / 无历史会话
  → 居中欢迎语 + 问题输入区
  → 选择仓库与分支后创建会话
  → 新会话进入左下历史列表，并切换到正常消息流

点击左下历史会话
  → 退出新建态，展示该会话的消息流与输入区
```

- `src/pages/CodeQaPage.tsx` 新增 `isStartingConversation`，阻止“自动选最近历史会话”覆盖用户显式发起的新会话。
- 左上“新建对话”进入居中提问态；创建成功或选择任一历史会话后退出该状态。删除当前会话后也回到居中提问态。
- 数据范围选择、会话创建、消息发送、历史持久化与权限校验均复用原有链路，不涉及后端改动。
- 验证：`npm run web:typecheck`、代码问答测试 24/24、`npm run build` 均通过；构建只保留已有的大 chunk 警告。


## 15. 默认进入新建会话页（V1.25.5）

`/ask` 每次首次挂载都以 `isStartingConversation=true` 进入居中新建会话页，不再根据左下历史记录自动打开最近会话。历史会话仅在用户主动点击时打开；创建成功后才进入新会话的正常消息流。

验证：`npm run web:typecheck`、代码问答测试 24/24 与 `npm run build` 均通过；Harness manifest 校验通过。
