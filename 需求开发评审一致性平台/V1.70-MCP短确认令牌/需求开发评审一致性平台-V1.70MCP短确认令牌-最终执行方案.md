# 需求开发评审一致性平台 V1.70：MCP短确认令牌最终执行方案

## 1. 背景与目标
线上截图显示客户端回传长确认令牌时遗漏正文片段，导致签名校验失败。将客户端需复制的值缩短，保持先核对、用户确认、再提交的现有流程。

## 2. 范围与非目标
修改 MCP 确认存储、令牌生成／校验、提示及测试。不修改 Bearer 连接凭据，不取消确认门禁，不涉及数据库、Worker、Functions 和前端业务页面。

## 3. 当前实现与问题
`confirm.mjs` 将完整确认内容编码后附加 HMAC；客户端必须准确回传长字符串。已有实例在回传时遗漏 `given_workspace` 编码片段。

## 4. 需求与验收标准
- 保持 `confirmation_token` 参数，值改为固定长度短随机引用，不包含需求正文。
- 服务端保存独立的确认快照；修改入参、返回对象或令牌不能改变已确认集合。
- 保留默认 15 分钟有效期及编号集合、项目组、窗口、分支、提交时间范围绑定；另绑定 MCP 调用身份。
- 随机引用不可猜测；残缺、伪造、过期、跨调用身份和另一实例的引用均拒收，不创建评审。
- 存储容量有上限，清理过期记录，容量耗尽时拒绝新确认，不驱逐尚有效记录。

## 5. 总体设计
当前 MCP 进程保存确认记录，以 `v2.` 加 24 字节密码学随机数的 base64url 编码（共 35 字符）作为引用。同一进程 HTTP 会话共享存储；核对返回引用，提交从存储读取快照后校验参数与身份。继续允许有效引用重试，沿用现有提交幂等路径。

## 6. 数据与接口设计
无数据库、RPC、API 参数新增。进程内 Map 上限 10000 条，签发时清理过期记录。`CRP_CONFIRM_TTL_MS` 保留；`CRP_CONFIRM_SECRET` 不再用于短引用，旧环境字段可保留但不产生共享存储能力。

## 7. 运行时改造
修改 `confirm.mjs`、`tools.mjs`、`index.mjs`、配置注释与 README。单实例重启清空确认记录；多实例需要请求固定到原实例，共享签名密钥不再足够。现有 Linux 单 MCP 容器无需额外配置。

## 8. 安全、兼容与回滚
不记录完整确认引用或凭据。旧 v1 令牌在升级后拒收，提示重新核对。发布或回滚后重新生成确认信息；不自动提交、不声称能从技术上证明自然语言中的用户同意。Bearer 鉴权保持原样。

## 9. 实施步骤与文件范围
已实现有界进程内确认存储及身份绑定，更新工具文案和配置说明，并覆盖短引用、篡改、过期、容量、实例与身份隔离及两步提交路径。产品版本已同步为 V1.70。

待用户提交并推送 `release`、构建并推送新应用镜像后，在 Linux 宿主机执行（默认获取最新镜像）：

```bash
cd /home/kduser/crp/app
git pull --ff-only origin release && \
bash deploy/supabase-selfhost/scripts/release.sh --apply
```

看到 MCP 更新及健康检查通过后，重新连接 Kiro MCP，重新发起核对并确认提交。验收确认编号以 `v2.` 开头、总长 35 字符、成功回执及平台实际生成的批次与需求集合一致。升级前令牌须丢弃，无需修改 Bearer token 或额外执行 SQL。
