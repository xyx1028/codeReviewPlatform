# V1.11 开发提交填写规范

> GitLab 的 MR（Merge Request）就是常说的 PR/合并申请。

## 只做 3 步

### 1. 复制需求编码

从需求 Excel 或平台复制完整编码，例如：`REQ-001`。

### 2. 在 IDEA 提交 Commit

打开 IDEA 左侧 **Commit** 工具窗口，把下面内容粘贴到 **Commit Message** 输入框：

```text
<修改说明>

Story-Id: REQ-001
```

示例：

```text
增加批量关闭订单接口

Story-Id: REQ-001
```

### 3. 在 GitLab 创建 MR

进入 **New merge request** 页面，填写 **Title** 和 **Description**。

**Title：**

```text
[REQ-001] <需求简述>
```

**Description：**

```markdown
## 关联需求
Story-Id: REQ-001

## 本次修改
- <修改内容>

## 验证情况
- [ ] <验证内容>

## 影响与风险
- 影响范围：<填写>
- 已知风险：<填写或无>
- 回滚方式：<填写>
```

## 3 个特殊情况

### 一个提交涉及多个需求

优先拆分；无法拆分时，每个编码独立一行：

```text
Story-Id: REQ-001
Story-Id: REQ-008
```

### 回滚代码

保留 `Revert`，补充原因和原需求编码：

```text
Revert "增加批量关闭订单接口"

回滚原因：旧版本客户端不兼容。

Story-Id: REQ-001
```

### 使用 Squash 合并

合并前检查最终 Commit，确保仍有：

```text
Story-Id: REQ-001
```

## 不要这样写

```text
Story-Id: 001                 ❌ 编码不完整
Story-Id: REQ-001, REQ-008    ❌ 多个编码挤在一行
处理一下 REQ-001              ❌ 只在正文提到，没有独立 Story-Id
```

## 提交前检查

- [ ] 编码从 Excel/平台复制，没有改写；
- [ ] Commit 末尾有独立的 `Story-Id`；
- [ ] MR 标题和描述都包含需求编码；
- [ ] Squash 后仍保留 `Story-Id`。

按以上格式提交即可，后续不需要开发人员逐条确认历史提交。
